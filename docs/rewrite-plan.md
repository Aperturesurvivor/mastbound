## 1. Ground rules

- **Independent implementation, MIT license.** SelfControl is GPL-3.0. We use
  its *ideas* (listed in §3), which are not covered by copyright. We do not
  copy, translate or paraphrase its source. Write code from this plan and
  the invariants document, not with SelfControl files open.
- **Reuse our own good code.** `HostsFileEditor`, the safe parts of
  `SecureFileIO` and `DomainValidator` are ours, MIT, and tested. Move them
  into the new core and keep their tests.
- **Core first, UI last.** Josiah builds the UI himself with AI tools such as
  Claude Code. Agents do not build or ship UI without his review.
- **Review gate after every phase.** Each phase ends with a short report:
  what changed, what was tested, what was not. Josiah approves before the
  next phase.
- **Never test enforcement on Josiah's main Mac.** It has a live block.
  Real-system tests run in a macOS virtual machine (§6, P3).

## 3. What we take from SelfControl, and what we do differently

| Topic | SelfControl | Mastbound |
| --- | --- | --- |
| End date | Root-owned settings file | Root-owned state file (same idea) |
| Extend | Later end date only, max 1 day per call | Later end date only, capped by D4 |
| Repair | Re-adds removed rules every 15 s | Same idea: check the hosts section each tick, rewrite if changed |
| Clock | Trusts the system clock | Credits monotonic time (D2) |
| Settings missing | Removes the block | Keeps the block (fail closed, I4) |
| IP blocking | Resolves IPs at start, edits `/etc/pf.conf` | Not in v1. Maybe a later experiment, own anchor only, never edits `pf.conf` |
| List | User types it | Ships a pinned adult list in the app |
| Max length | 24 h default | 365 days |

## 4. Design

### 4.1 Package layout

```
Sources/
  MastboundCore/     pure logic, no root, no real files; fully unit tested
    Commitment.swift        state machine (start, extend, tick, recover)
    TimeCredit.swift        clock crediting (D2)
    Blocklist.swift         load bundled list, check SHA-256
    HostsSection.swift      from HostsFileEditor (reuse)
    DomainValidator.swift   reuse
    FileStore.swift         atomic write, owner/mode checks (from SecureFileIO)
  mastboundd/        root daemon run by launchd; thin loop over Core
  mastboundctl/      root CLI; the only way to change state
Resources/
  adult-domains.txt          pinned list, generated by script/make-list.sh
Tests/
  MastboundCoreTests/        unit tests
  IntegrationTests/          daemon + ctl against a temp folder, no root
```

All system paths come from one `Paths` value, so tests can point them at a
temp folder.

`start` copies `mastboundd`, `mastboundctl` and the list into root-owned
`/Library/PrivilegedHelperTools/Mastbound/`. The launchd plist points there,
not into the app, so deleting the app does not stop the block (I8).

Invariant coverage: I1, I10 → `HostsSection` + daemon loop; I2, I3 →
`Commitment` + §4.4; I4, I11 → `FileStore` + daemon loop; I5 → §4.2;
I6 → `TimeCredit`; I7, I8, I9 → P2 and P3 tests; I12 → `Blocklist`.

### 4.2 State

One root-owned file: `/Library/Application Support/Mastbound/state.json`,
mode `0600`. A second file, `status.json`, mode `0644`, holds only the phase
and end date, so the UI can read it without a password. No state lives in
the user's home folder (I5).

```
State {
  phase: none | active | recovering | expired
  startedAt, endsAt: Date
  durationSeconds, creditedSeconds: Int
  lastTickWall: Date, lastTickMonotonic: UInt64
  listSHA256: String
  recoverAt: Date?          // only in phase recovering
}
```

### 4.3 Time credit (D2)

Implemented in `Sources/MastboundCore/Clock.swift`.

- Same boot (same `kern.bootsessionuuid`): credit only the monotonic change
  (`mach_continuous_time`, which counts sleep). The wall clock is not used,
  so clock changes in either direction have no effect.
- After a reboot the monotonic clock restarts. Credit the wall-clock change
  since the last saved tick, or 0 if it went back. This is a documented limit:
  a clock change made while the Mac is off is accepted.

The commitment ends when `creditedSeconds ≥ durationSeconds`. `endsAt` is
only for display.

### 4.4 Commands (`mastboundctl`)

| Command | Root | Allowed in | Effect |
| --- | --- | --- | --- |
| `status` | no | any | Print phase, end date, time left |
| `install` | yes | any | Install or upgrade files and the daemon; keeps the state |
| `start --hours N` / `--days N` | yes | idle | Install, then start a commitment |
| `extend --hours N` / `--days N` | yes | active, recovering | Add time; never subtracts |
| `recover --cancel` | no | recovering, or active with an open app flow | Back to active, flow closed (non-root: request file, daemon acts within 5 s) |
| `recover --begin` | yes | active | Opens the app flow: records the credited time; nothing unblocks |
| `recover --finish PHRASE` | yes | active with an open app flow | Refused before 1 hour of credited time since `--begin`; then recovering |
| `uninstall` | yes | idle | Remove daemon and files |

The UI will call these commands with one admin prompt. This table is the
contract between the core and Josiah's UI.

### 4.5 Daemon loop

Every 5 s: read state → update credit → decide phase → make the hosts section
match the phase → write state. Any error leaves `/etc/hosts` unchanged and
logs once per minute, not every tick.
